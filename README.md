# Мини-PDM: Состав изделия

Настольное приложение, которое импортирует выгрузку CAD-системы, хранит изделие как
состав деталей и сборок, считает массу и ведёт версии с рабочим жизненным циклом.

## Что умеет

- **Импорт выгрузки CAD-системы.** Разбор JSON-документов сборок (`.a3d`), деталей
  (`.m3d`) и стандартных изделий. Каждый файл разбирается независимо: одна ошибка не
  останавливает импорт остальных.
- **Проверка данных.** Обозначения изделий проверяются по шаблону ЕСКД
  `^[А-ЯЁ]{4}\.\d{6}\.\d{3}$`. Стандартные изделия обозначений не имеют. Деталь без
  массы принимается с предупреждением, а не отклоняется: расчёт массы изделия
  помечается как неполный, но остаётся полезным.
- **Версии.** Переходы `В работе → Утверждена`, `В работе → Аннулирована`,
  `Утверждена → Аннулирована`. Аннулированная версия выпадает из состава и расчётов,
  а текущей становится последняя неаннулированная.
- **Повторный импорт.** Действующая версия правится на месте, утверждённая не
  трогается — для изменённого изделия заводится следующая версия.
- **Расчёты.** Масса с учётом количества по всем уровням вложенности, сводная
  спецификация без корневой сборки, поиск циклов в составе по графу прямых связей.
- **Отчёт импорта с фильтром по результату.** Строки делятся на принятые, принятые с
  замечанием и отклонённые; в каждой указано, что именно не так и что делать. Если
  в выгрузке есть отклонения, отчёт открывается сразу на них. Счётчик над таблицей
  показывает, сколько строк видно сейчас и по скольким в выгрузке.
- **Поиск.** По обозначению или наименованию. Символы `%`, `_` и `\` ищутся буквально.
- **Экспорт спецификации в CSV** в кодировке UTF-8 с разделителем `;` — открывается
  в Excel без настройки импорта.

## Требования

- .NET 8 SDK или новее. В `Directory.Build.props` включён `RollForward=LatestMajor`,
  поэтому приложение запускается и на более новой версии среды.
- PostgreSQL 14 и новее — основная база. SQLite используется в тестах и удобен для
  локального запуска без установки сервера.

## Сборка и запуск

```bash
dotnet restore
dotnet build
dotnet test
dotnet run --project src/MiniPdm.Wpf
```

При первом запуске схема базы создаётся сама, отдельная команда не нужна.

## Настройка базы

Параметры подключения читаются из `src/MiniPdm.Wpf/appsettings.json`:

```json
{
  "Database": {
    "Provider": "PostgreSql",
    "ConnectionString": "Host=localhost;Port=5432;Database=minipdm;Username=minipdm;Password=minipdm",
    "ApplySchemaOnStartup": true
  }
}
```

- `Provider` — `PostgreSql` или `Sqlite`.
- `ApplySchemaOnStartup` — создавать таблицы и индексы при старте.
- Для SQLite достаточно указать путь к файлу:
  `"ConnectionString": "Data Source=minipdm.db"`.

### PostgreSQL в Docker

```bash
docker compose up -d
```

Сервис поднимает PostgreSQL 16 на порту `5432` с логином и паролем `minipdm` и
базой `minipdm`, что совпадает с настройками по умолчанию. Ожидание готовности:

```bash
docker compose ps
```

## Структура решения

| Проект | Назначение |
| --- | --- |
| `MiniPdm.Domain` | Типы предметной области: обозначения, состояния версий, правила переходов. Зависимостей нет. |
| `MiniPdm.Application` | Сценарии: импорт, жизненный цикл, расчёты, запросы для интерфейса. |
| `MiniPdm.Infrastructure` | Реализация на Dapper: подключения, репозиторий, схема, чтение файлов выгрузки. |
| `MiniPdm.Wpf` | Интерфейс: дерево состава, карточка объекта, отчёт импорта, спецификация. |
| `MiniPdm.Tests` | Тесты, включая сквозные проверки на данных из `cad-export.zip`. |

Схемы баз лежат в `db/schema.postgres.sql` и `db/schema.sqlite.sql`.

## Формат данных на входе

Документ — JSON со следующими полями:

| Поле | Смысл |
| --- | --- |
| `formatVersion` | Версия формата выгрузки. |
| `type` | `assembly`, `part` или `standardPart`. |
| `designation` | Обозначение по ЕСКД. У стандартных изделий отсутствует. |
| `name` | Наименование. |
| `material`, `massKg` | Материал и масса одного экземпляра в кг. |
| `components` | Состав: имя файла компонента и количество. Только для сборок. |

Состав хранится в отдельной таблице связей, а не в текстовом поле, поэтому
изменение состава при повторном импорте не требует разбора JSON заново.

## Проверка на реальных данных

В репозитории лежит архив `cad-export.zip` с папками `cad-export` и
`cad-export-v2`. Сквозные тесты `CadExportFixtureTests` работают с ним напрямую:

- первый импорт: 45 документов, 38 принято, 7 отклонено, 1 предупреждение;
- повторный импорт той же выгрузки не создаёт новых версий;
- после утверждения изменённых изделий импорт `cad-export-v2` заводит вторые
  версии, а их масса и состав обновляются;
- без утверждения правится та же рабочая версия.

Проверить сценарий вручную: импортировать `cad-export`, утвердить изменённые
изделия, затем импортировать `cad-export-v2` и сравнить версии в карточке.

## Особенности реализации

- **Текущая версия хранится явно** в `current_version_id`. Список версий отсортирован
  по номеру, но именно ссылка определяет рабочую версию: после аннулирования самой
  новой рабочей становится предыдущая.
- **Циклы ищутся по графу связей**, а не по раскрытому дереву: дерево ограничено
  глубиной и цикл в нём не виден. Перед поиском номера версий родителей
  переводятся в номера объектов — разные пространства идентификаторов нельзя
  смешивать, иначе цикл терялся бы или случайное совпадение принималось за
  замыкание.
- **Объект опознаётся по файлу-источнику, затем по обозначению и лишь потом по
  наименованию.** Это позволяет обновить существующее изделие, даже если файл и
  наименование переименовали, не упёршись в уникальный индекс.
- **Папка выбирается диалогом Windows Forms.** В .NET 8 своего диалога выбора папки
  в WPF нет, а вариант на `Shell.Application` показывает лишнее окно.
